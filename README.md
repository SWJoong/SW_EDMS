> **Antigravity AI 개발 프롬프트 가이드 & 웹 어플리케이션 개발 샘플**

## 🚨 먼저 읽어주세요 — 이 샘플의 보안·무결성 한계

> **이 저장소는 "바이브코딩 학습 교재"입니다. 지금 이대로 실제 근태·회계 기록을 담는 운영 시스템으로 쓰면 안 됩니다.**

전자결재는 하필 **기록 무결성 요구가 가장 높은 영역**이라, 자체 제작 난이도가 최상위입니다.
외부 전자결재 업체 문서가 지도점검을 통과하는 이유는 기술이 뛰어나서가 아니라
**"기록을 만드는 주체"와 "기록을 보관하는 주체"가 분리**되어 있기 때문입니다.

현재 배포 코드는 **브라우저 `localStorage` 목업**이라 다음이 **원리적으로 불가능**합니다.

- ⛔ **인증·권한 없음** — `localStorage` 값만 바꾸면 누구나 "관장"이 됩니다(역할 표시는 화면 장식).
- ⛔ **서버 시각 없음** — 결재 일시가 결재자 PC 시계로 저장돼 조작 가능(타임존도 없음).
- ⛔ **위·변조/삭제 흔적 없음** — 승인 후에도 휴가일수·여비·시간외시간을 바꿔치기할 수 있고, 지운 기록은 흔적이 없습니다.
- ⛔ **접속기록 없음** — 병가 사유 등 건강(민감)정보를 조회·출력해도 남는 기록이 0건.

이번 커밋에서 접수된 9가지 지적과 추가 발견 지점을 **DB 스키마 층에서 전면 보완**하고
(해시체인·append-only·서버시각·RLS·권한분리·접속기록), 데모 코드에는 **원리 시연 + 한계 주석**을 달았습니다.
**무엇을 어떻게 고쳤고, 무엇은 원리적으로 못 고치는지**는 아래 문서에 정직하게 정리했습니다.

> 📄 **자세한 분석·조치 내역: [docs/SECURITY.md](docs/SECURITY.md)**
> 🗄️ **무결성 강화 스키마: [docs/supabase_schema.sql](docs/supabase_schema.sql)**

핵심 결론부터: **"조작을 막는다"는 약속은 지도점검에서 오히려 신뢰를 잃습니다.**
단일 Supabase 프로젝트에서 소유자(service_role)는 무엇이든 할 수 있기 때문입니다.
목표는 **"조작하면 흔적이 남는다"**로 잡고, 매일 체인헤드 해시를 **외부(이사장·회계사 메일·별도 저장소)로 앵커링**해야 합니다.

## 🧭 무결성 요구 수준별 바이브코딩 관리 가이드

**모든 프로그램에 같은 수준의 보안이 필요한 게 아닙니다.** "담으려는 기록이 조작·삭제되면 누가 얼마나 곤란한가"로
등급을 먼저 정하고, 등급이 도구를 결정하게 하세요. 바이브코딩은 **낮은 등급부터 시작**하는 게 정석입니다.

### 판별 질문 (담으려는 기록에 대해)
1. 이 기록이 **법으로 보존 의무**가 있나? (근태·회계·인사·민감정보 → 예)
2. 조작·삭제되면 **돈·근태·평가·법적 책임**에 영향을 주나?
3. **개인정보/민감정보(건강·장애 등)**가 들어가나?
4. **여러 사람**이 이 기록을 신뢰하고 근거로 삼나?

→ "예"가 많을수록 상위 등급. 하나라도 1~3번에 해당하면 **자체 바이브코딩만으로는 위험**합니다.

### 등급표

| 등급 | 예시 기능 | 조작·삭제되면? | 최소 요구사항 | 바이브코딩 판단 |
|------|-----------|----------------|----------------|-----------------|
| **A. 최고 무결성**<br/>(법정 보존·감사 대상) | **전자결재·근태·회계·인사**, 급여, 개인정보/민감정보 대장, 후원금 관리 | 지도점검 지적, 법적 책임, 소송 증거 훼손 | 위·변조 방지, 서버 시각, append-only + 해시체인, 접속기록 2년+·월1회 점검, 권한 분리, **보관 주체 분리**, 백업/복구 | ❌ **자체 제작 지양.** 검증된 상용 전자결재/문서보존 솔루션 사용을 **우선** 검토. 굳이 만든다면 이 저장소의 강화 스키마 + 외부 앵커링 + **전문가 검토** 필수 |
| **B. 중간 무결성**<br/>(내부 운영 기록) | 회의록, 공지·게시판, 자산·비품 대장, 재고, 단순 내부 승인, 상담 일지(비민감) | 되돌리기 번거롭고 신뢰 저하, 업무 혼선 | 로그인·권한, DB(Supabase 등), 변경 이력, 정기 백업, 민감정보 **배제** | △ **가능하되 조건부.** Auth + DB + 백업을 갖추고 시작. 민감정보는 담지 않기 |
| **C. 낮은 무결성**<br/>(편의·시각화) | **자원(회의실·차량·노트북) 예약**, 일정/근무현황 **시각화**, 대시보드, 설문 취합, 안내·소개 페이지, 계산기 | 틀려도 다시 만들면 됨, 영향 국소적 | 거의 없음(사용 편의 위주) | ✅ **적극 권장.** 바이브코딩은 **여기서부터** 시작하세요 |

> 이 저장소로 치면 **근태·결재(A등급)** 는 검증된 도구가 맡고,
> **자원 예약·일정 시각화(C등급)** 부터 바이브코딩으로 직접 만들어 익히는 것이 안전하고 실용적인 순서입니다.

### 등급을 넘나들 때의 3원칙
1. **등급부터 정하고 시작한다** — "무엇을 만들까"보다 "어떤 기록을 담을까"가 도구를 결정합니다.
2. **민감정보는 애초에 담지 않는다** — 병가 사유는 진단명 자유텍스트 대신 **코드값 + 증빙 첨부**. 수집을 최소화하면 지켜야 할 것도 줄어듭니다.
3. **만드는 나와 검증하는 장치를 분리한다** — 스스로 채점하지 말 것. 해시체인·외부 백업·제3자 보관·전문가 리뷰가 "검증하는 손" 역할을 합니다.

## 🤖 Antigravity AI 프롬프트 기반 앱 제작 가이드

본 시스템은 **Antigravity AI 에이전트**와 대화하며 단계적으로 구축되었습니다. 에이전트를 효율적으로 활용하는 프롬프트 작성 노하우를 소개합니다.

### 🎯 Step 1: `/goal` 프롬프트로 기초 골격 및 MVP 요구사항 정의

> 첫 번째 단계에서는 **도메인 특성, 사용자 수, 수직적 조직 구조, 필수 결재 서류 7종, 날인 첨부 요구사항, 기술 스택 및 배포 계획**을 명확히 정의하여 프로젝트 전체 아키텍처와 기본 UI/UX를 구축합니다.

#### 💬 입력한 프롬프트 (Prompt #1):
```text
/goal 사회복지기관에서 사용할 E-HR 형식의 전자결재 시스템을 제작할 예정입니다. 기관 규모는 최대 5~50명 사이로 잡습니다. 최고 결정권자(센터장, 관장 등), 중간 관리자(사무국장, 과장, 팀장, 주임 등), 실무자(사회복지사) 형식의 수직적 조직문화를 기반으로 하며, OU를 설정할 수 있어야 합니다.
날인 이미지가 문서 내에 첨부 가능해야 합니다.
```

## ✨ 주요 기능 (Features)

### 📄 1. 전자결재 서류 7종 제공
- **연차사용신청서**: 반차/연차 자동 계산 및 잔여 연차 연동
- **근무상황부2**: 공가, 병가, 경조사 등 특수 휴가 사유 작성 및 증빙 첨부
- **출장신청서**: 카카오맵 기반 출장지 검색, 여비 품의 자동 계산
- **시간외근무명령서**: 사전 시간외 근무 신청 및 승인 프로세스
- **시간외근무확인서**: 실제 근무 시간 검증 및 실적 등록
- **교육신청서**: 직무 교육 신청 및 관련 예산 신청
- **교육결과보고서**: 교육 이수 후 결과 및 소감 보고서 작성

### 🖋️ 2. 전자 날인/도장 서명 기능
- 사용자별 도장/서명 이미지 등록 및 결재 완료 시 결재란에 실시간 반영

### 🏢 3. 수직적 조직도 (OU) & 결재선 지정
- 센터장 / 사무국장 / 팀장 / 사회복지사 등 조직도 계층 트리 조회 및 자동 결재선 지정

### 📅 4. 근무현황 시각화 & 구글 캘린더 연동
- 전체 직원의 출장, 휴가, 시간외 근무 일정을 타임라인/캘린더 뷰로 시각화

### 💻 5. 자원 및 미팅 예약 시스템
- 회의실, 노트북, 기관 차량 등 공용 자원 예약 및 미팅 일정 관리

### 🗺️ 6. 카카오맵 연동 출장 여비 품의
- 출발지/목적지 검색을 통한 경로 및 이동거리 산출, 여비 산정 기능

## 🚀 시작하기 (Getting Started)

### 사전 준비 사항
- Node.js (v18 이상 권장)
- npm 또는 yarn

### 설치 및 실행

1. 저장소 클론 (Clone repository)
   ```bash
   git clone https://github.com/SWJoong/SW_EDMS.git
   cd SW_EDMS
   ```

2. 패키지 설치 (Install dependencies)
   ```bash
   npm install
   ```

3. 개발 서버 실행 (Run development server)
   ```bash
   npm run dev
   ```

4. 브라우저 접속
   - `http://localhost:5173` 접속하여 앱 확인
